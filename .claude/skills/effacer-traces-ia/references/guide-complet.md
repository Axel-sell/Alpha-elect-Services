# Les tics de l'IA : la liste complète

Adapté du guide de MEZES Corporation (« Les tics de l'IA : la liste complète », ressource MEZES, @mezes131). Chaque tic est présenté avec un exemple « version IA », la « version humaine » quand le guide en donne une, et la correction.

Rappel : aucun de ces signes n'est une preuve d'IA à lui seul. C'est l'accumulation et la répétition systématique qui rendent un texte artificiel.

## 1. Ponctuation et typographie

### 1.1 Le tiret cadratin « — »

Le plus célèbre. L'IA l'utilise pour tout : incises, pauses, rebondissements.

- Version IA : Le projet a pris du retard — mais l'équipe a tenu bon.
- Version humaine : Le projet a pris du retard, mais l'équipe a tenu bon.
- Correction : remplace-le par une virgule, deux points, des parenthèses ou un point.

### 1.2 Les deux-points dramatiques

Pour créer un faux suspense.

- Version IA : Le résultat : spectaculaire.
- Version humaine : Le résultat a dépassé nos attentes.

### 1.3 Le gras partout

Quand tout est important, plus rien ne l'est.

- Version IA : Il est **essentiel** de **tester ton code** avant **chaque déploiement**.
- Version humaine : Teste ton code avant chaque déploiement.
- Correction : un mot en gras par paragraphe au maximum, et seulement s'il change vraiment la compréhension.

### 1.4 Les émojis devant les titres et les puces

- Version IA : 🚀 Introduction, ✅ Avantages, 💡 Astuce, 🎯 Objectif…
- Correction : zéro émoji dans les titres, la documentation et le code. Garde-les pour les messages informels, et seulement si c'est ton style.

### 1.5 Les majuscules à chaque mot des titres

Une habitude héritée de l'anglais, incorrecte en français.

- Version IA : Les Meilleures Pratiques Pour Sécuriser Ton API
- Version humaine : Les meilleures pratiques pour sécuriser ton API

### 1.6 Les guillemets anglais dans un texte français

- Version IA : Clique sur "Valider".
- Version humaine : Clique sur « Valider ».

## 2. Structure

### 2.1 La règle de trois

Trois adjectifs, trois exemples, trois puces. Toujours trois.

- Version IA : Une solution simple, rapide et efficace.
- Version humaine : Une solution simple à mettre en place.
- Correction : donne le nombre d'éléments dont tu as réellement besoin. Un, deux, quatre, c'est très bien aussi.

### 2.2 Les fragments en rafale

- Version IA : Simple. Rapide. Efficace.
- Version humaine : C'est simple à utiliser, et ça va vite.

### 2.3 Des titres et des puces pour tout

Une réponse de trois phrases découpée en sections, avec des sous-titres et des listes.

- Correction : un paragraphe suffit tant que le texte tient en quelques lignes. Les listes servent à comparer ou à suivre des étapes.

### 2.4 L'introduction qui reformule la question

- Version IA : Excellente question ! La sécurisation d'une API est un sujet crucial que beaucoup de développeurs se posent.
- Version humaine : Pour sécuriser ton API, commence par l'authentification.
- Correction : réponds dès la première phrase.

### 2.5 La conclusion qui résume tout

« En résumé… », « En conclusion… », « Pour récapituler… », suivi de ce qu'on vient de lire.

- Correction : termine sur la dernière information utile, ou sur une action concrète.

### 2.6 La question d'engagement finale

« N'hésite pas à me poser d'autres questions ! », « Souhaites-tu que je développe ce point ? »

- Correction : supprime-la, sauf si une vraie question reste ouverte.

### 2.7 Le rythme trop régulier

Des paragraphes de la même longueur, des phrases de la même taille, la même structure répétée.

- Correction : alterne. Une phrase courte. Puis une phrase plus longue, qui prend le temps d'expliquer une nuance ou de donner un exemple.

## 3. Tournures de phrases

### 3.1 « Ce n'est pas X, c'est Y »

La tournure la plus repérable après le tiret cadratin. Variantes : « Ce n'est pas seulement X, c'est aussi Y. », « Il ne s'agit pas de X, mais de Y. », « Plus qu'un X, c'est un véritable Y. »

- Version IA : Ce n'est pas qu'un outil, c'est une véritable révolution.
- Version humaine : Cet outil a changé notre façon de travailler.
- Correction : affirme directement ce que tu veux dire, sans opposer à quelque chose que personne n'a dit.

### 3.2 La question rhétorique suivie de sa réponse

- Version IA : Le secret ? La régularité.
- Version humaine : Le plus important, c'est la régularité.

### 3.3 Les formules de remplissage

« Il est important de noter que… », « Il convient de souligner que… », « Force est de constater que… », « Il va sans dire que… »

- Correction : supprime la formule et garde l'information.

### 3.4 Les ouvertures grandiloquentes

« Dans un monde en constante évolution… », « À l'ère du numérique… », « Dans le paysage technologique actuel… »

- Correction : commence par le fait concret.

### 3.5 Les invitations au voyage

« Plongeons dans… », « Explorons ensemble… », « Partons à la découverte de… »

### 3.6 « Que tu sois X ou Y »

- Version IA : Que tu sois débutant ou expert, ce guide est fait pour toi.
- Correction : parle à ton vrai lecteur, et assume-le.

## 4. Vocabulaire

### 4.1 Les mots gonflés

Ils reviennent dans presque tous les textes générés.

| Mot ou expression IA | Ce qu'on dirait plutôt |
|---|---|
| crucial, essentiel, primordial | important, ou rien du tout |
| incontournable | utile, connu, très utilisé |
| robuste | fiable, solide |
| fluide, intuitif | simple, facile à utiliser |
| optimiser, maximiser | améliorer, accélérer |
| un véritable levier | un moyen |
| révolutionner, transformer | changer |
| au cœur de | dans, au centre de |
| témoigne de | montre |
| l'écosystème, le paysage | le marché, le secteur, les outils |
| naviguer (au sens figuré) | gérer, s'en sortir |
| booster | augmenter |
| un game changer | un vrai changement |

### 4.2 L'enthousiasme permanent

« Incroyable », « puissant », « fascinant », « extraordinaire »… pour décrire un simple formulaire.

- Correction : garde les superlatifs pour ce qui les mérite vraiment.

### 4.3 Les précautions en cascade

- Version IA : Cette méthode peut potentiellement contribuer à améliorer généralement les performances.
- Version humaine : Cette méthode améliore les performances dans la plupart des cas.

## 5. Ton

### 5.1 La flatterie

« Excellente question ! », « Quelle idée brillante ! », « Tu as tout à fait raison ! »

### 5.2 La neutralité molle

- Version IA : Les deux approches ont leurs avantages et leurs inconvénients, tout dépend de tes besoins.
- Version humaine : Pour un projet de cette taille, prends la première approche.
- Correction : donne une recommandation claire, puis la condition dans laquelle elle change.

### 5.3 Les excuses et disclaimers inutiles

« En tant qu'IA… », « Je ne suis pas en mesure de… », « Il est recommandé de consulter un professionnel… », pour une question simple.

## 6. Dans le code

### 6.1 Les commentaires qui répètent le code

Version IA :

```js
// Incrémente le compteur de 1
counter++;
```

- Correction : commente le pourquoi, jamais le quoi. Si le code est clair, aucun commentaire n'est nécessaire.

### 6.2 Les commentaires décorés

Version IA :

```js
// ✅ Fixed: handle edge case — now works perfectly!
// 🚀 Optimized for performance
```

- Correction : pas d'émoji, pas de tiret cadratin, pas d'enthousiasme dans les commentaires.

### 6.3 Les noms génériques

`data`, `result`, `item`, `temp`, `handleData()`, `processInfo()`, `utils.js`, `helpers.js`, `DataManager`…

- Correction : nomme selon le métier : `pendingOrders`, `computeTaxAmount()`, `invoiceFormatter.js`.

### 6.4 La gestion d'erreurs défensive partout

Version IA :

```js
try {
  const total = a + b;
} catch (error) {
  console.error("An error occurred:", error);
}
```

- Correction : gère les erreurs là où elles peuvent réellement arriver (réseau, fichiers, saisie utilisateur), avec un traitement utile.

### 6.5 Le code « au cas où »

Des options de configuration jamais utilisées, des fallbacks pour des cas impossibles, des fonctions génériques pour un seul appel.

- Correction : écris le code dont tu as besoin aujourd'hui.

### 6.6 Le README gonflé

Une dizaine de badges, des sections « ✨ Features », « 🚀 Getting Started », « 🤝 Contributing » vides, et un « Built with ❤️ » à la fin.

- Correction : un README utile répond à trois questions : à quoi sert le projet, comment l'installer, comment le lancer. Le reste seulement si c'est vrai et utile.

### 6.7 Les messages de commit verbeux

Version IA :

```
✨ Enhanced user experience by refactoring the authentication module
for better readability, maintainability and scalability
```

Version humaine :

```
Corrige l'expiration du jeton de session
```

- Correction : court, à l'impératif, factuel.

### 6.8 Le mélange des langues

Des commentaires en anglais, des messages d'erreur en français, des noms de variables dans les deux langues.

- Correction : choisis une langue par usage (code, commentaires, interface) et tiens-la partout.

## 7. La règle à copier-coller

Bloc prévu par le guide pour les fichiers d'instructions des assistants : `CLAUDE.md` à la racine du projet (Claude Code), `.cursor/rules/` (Cursor), `.github/copilot-instructions.md` (GitHub Copilot), `AGENTS.md` (Codex et autres agents), ou les instructions personnalisées du compte (ChatGPT, Claude, Gemini).

```markdown
## Règles d'écriture (texte, documentation et code)

### Ponctuation et mise en forme
- N'utilise jamais le tiret cadratin (—) ni le tiret demi-cadratin (–) comme ponctuation. Utilise une virgule, deux points, des parenthèses ou un point.
- N'utilise aucun émoji dans les titres, la documentation, les commentaires ou les messages de commit.
- Utilise le gras au maximum une fois par paragraphe, seulement si c'est indispensable.
- En français, n'écris pas les titres avec une majuscule à chaque mot, et utilise les guillemets « ».
- N'utilise des titres et des listes que si le contenu le justifie. Un texte court s'écrit en paragraphes.

### Structure
- Réponds dès la première phrase, sans reformuler la question ni complimenter.
- Ne termine pas par un résumé de ce qui vient d'être dit, ni par une question du type « Souhaites-tu que… ».
- N'utilise pas systématiquement des groupes de trois (adjectifs, exemples, puces).
- Évite les fragments en rafale (« Simple. Rapide. Efficace. »).
- Varie la longueur des phrases et des paragraphes.

### Tournures interdites
- « Ce n'est pas X, c'est Y », « pas seulement X, mais aussi Y », « plus qu'un X, un véritable Y ».
- Les questions rhétoriques suivies de leur réponse (« Le secret ? La régularité. »).
- « Il est important de noter que », « Il convient de souligner que », « Force est de constater ».
- « Dans un monde où », « À l'ère du numérique », « Dans le paysage actuel ».
- « Plongeons dans », « Explorons », « Que tu sois X ou Y ».

### Vocabulaire
- Évite : crucial, essentiel, primordial, incontournable, robuste, fluide, optimiser, levier, révolutionner, au cœur de, témoigne de, écosystème, paysage, naviguer (au sens figuré), booster, game changer.
- Pas de superlatifs ni d'enthousiasme sans raison. Pas de flatterie.
- Donne des recommandations claires plutôt que des précautions en cascade.

### Code
- Commente uniquement le pourquoi, jamais ce que le code fait déjà clairement.
- Nomme les variables, fonctions et fichiers selon le métier, jamais data, result, temp, utils, helper ou Manager sans précision.
- Gère les erreurs seulement là où elles peuvent réellement survenir, avec un traitement utile.
- N'ajoute ni option, ni fallback, ni abstraction qui ne sert pas aujourd'hui.
- Messages de commit courts, à l'impératif, factuels, sans émoji.
- README : à quoi sert le projet, comment l'installer, comment le lancer. Rien de plus sans raison.
- Une seule langue par usage (code, commentaires, interface), tenue partout.
```

## 8. La checklist de relecture

Avant de publier un texte ou de valider du code généré, vérifie en 30 secondes :

- [ ] Aucun tiret cadratin « — » utilisé comme ponctuation
- [ ] Aucun émoji dans les titres, le code ou la documentation
- [ ] Pas de « ce n'est pas X, c'est Y »
- [ ] Pas de liste systématiquement en trois points
- [ ] La première phrase répond directement
- [ ] Pas de résumé ni de question d'engagement à la fin
- [ ] Le gras est rare
- [ ] Aucun mot de la liste du 4.1
- [ ] Les commentaires expliquent le pourquoi
- [ ] Les noms de variables parlent du métier

L'astuce finale : lis ton texte à voix haute. Si une phrase sonne comme une publicité ou une brochure, réécris-la comme tu l'expliquerais à un collègue.
